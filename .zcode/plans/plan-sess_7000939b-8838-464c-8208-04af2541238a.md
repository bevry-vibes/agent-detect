# Plan: the introspection surface — `explain` + `found` — fixture channels, and trailer-selection guidance

## Layer taxonomy (evidence/raw vs reasons — the consolidation verdict)

Two different "why" layers, separate payloads, shared plumbing:

| | `found` (today's dev-only `raw` action) | `explain` (new) |
|---|---|---|
| answers | *what did the ladder observe on this machine?* | *why did the verdict come out as it did, and what now?* |
| content | process_lineage, evidence claims, detectable/detected, *-urls, platform/version | per-entity reason codes (which rung fired), judged values, sources, remediation actions, alternatives |
| audience | debugging detection, rule contributions ("what I saw") | any agent/user hitting exit 8/9/10 who needs to act |
| level | implementation detail | consumer interpretation |

Payloads do not merge (similar but too different); plumbing consolidates: both released, both built from the same `Detection`, both mirror the tri-state in exit codes, `explain` points to `found` for the observation trail.

Pure, no I/O; classification mirrors the ladder's rung order (scandal → `enforced` → setting `enabled` → `disabled` → `never`/`opt-*` → NOASSERTION/null; `resolveAxisClosed` core.zig:2421-2436, `modelReciprocityOf` core.zig:2453-2463). `values` carries judged pairs inline (`closed_setting = enabled`) so explain is self-contained.

Action mapping:
- `harness_setting_enabled` → `fix_setting` (per-harness hint via new optional `closed_setting_hint: ?[]const u8 = null` on `HarnessRule` rules.zig:556; generic fallback when null; zcode "Improve experience" first per README.md:74).
- `*_scandal` → `switch_entity` + `read_policy`. `*_closed_enforced`/`*_closed_opt`/`model_closed` → `switch_entity` + `preflight_combo` (`agent-detect check-reciprocal --harness=… --provider=… --model=…`).
- `*_training_unsourced` / `model_openness_unknown` / `harness_unmatched` / `*_unreadable` → `contribute_data` — **referring to both** (direct `agent-detect found` command for evidence + CONTRIBUTING.md url for the workflow; the dual reference is deliberate: found is immediately runnable, CONTRIBUTING.md carries the submission process) — plus `preflight_combo` where recipe mode can bypass.
- Exit 6 (sqlite3) stays a one-line stderr append, not a Reason.

## Workstream 2 — the introspection surface

### 2a. `agent-detect explain` (new, released)

Live + recipe mode; no identity-completeness gate (exit-8 states yield `harness_unmatched`/`*_unreadable` reasons); exit mirrors state (0/8/9/10; 4/7 as usual). Output (`buildExplain`, manual-`std.json.Value` pattern per core.zig:2507-2577) — **identity carries harness/provider/model only, no agent_id** (it stays derivable from the trio; no loss):

                 "values": [{ "name": "closed_training", "value": "enforced" }],

                 "actions": [ { "kind": "contribute-data", "instruction": "…",

### 2b. `agent-detect found` (the dev `raw` action, promoted and renamed)

- Move `buildRaw` (dev.zig:355-420), `buildDeclaredRaw` (dev.zig:340-350), and `platformId()` if dev-local, into `src/lib/core.zig` (they already use core's pub helpers); dev.zig imports them; capture call sites (dev.zig:2156, 2746) switch the emitted key to `found`.
- Behavior change vs `runRawAction` (dev.zig:426-445): emit the block even when identity is incomplete (exit 8 still returned) — observations are most wanted exactly when detection failed (today the block is built then discarded). Capture path unaffected (refuses partial before the action).
- Recipe mode free via shared `runAction` dispatch (`buildDeclaredRaw` for combos).
- Docs: `fixturesUsage`/CONTRIBUTING.md action-word references become `found`.

### 2c. stderr — both, layered

`check-reciprocal`/`identify` failures keep the byte-stable registry first line, then a compact derived layer — one line per failing entity with its judged value and the explain pointer (no action text, no URLs):

```
agent (harness, provider, model) data complete and requirement failed
  - provider: closed_training = enforced (see: agent-detect explain)
```

Single source of truth (`reasonsFor`); either-explain-only costs every consumer a second invocation for the basic question, either-stderr-only forces prose parsing — both-layered ≈ cost of one (~30-line renderer).

**A′ (recommended)**: `explain` + `found` + layered stderr; identify keyset untouched. **B** (identify gains `reasons`) remains available later — it reuses `reasonsFor` — but costs the frozen-keyset break (fixture.d.ts, known_fixtures keyset, regeneration over 2,790 from-identity + injection into 192 from-capture). **C** (stderr-only) is subsumed by A′.

## Workstream 3 — fixture channels (new-key adoption without touching existing files)

- **Key rename `raw` → `found`, going forward only**: new writes (captures, regeneration waves) emit `outputs.found`; existing committed fixture files keep `outputs.raw` untouched — no back-edit migration. `fixtures/fixture.d.ts` documents `found` as the channel with `raw` as the legacy alias; `known_fixtures.test.zig` accepts either (same payload shape, so validation logic is shared).
- **`explain` channel**: `outputs.explain` = the `buildExplain` JSON. Deterministic and pure from `Detection` + rules, so from-identity fixtures derive it via `resolveRecipe` (zero-token) and captures build it in-process at capture time. Failure-state explains (scandal providers, closed models, NOASSERTION combos) live naturally in from-identity fixtures; captures (which refuse partial) carry clean-state explains.
- **stderr channels, dotted-key convention, arrays not multiline strings**: when an action emitted stderr, it is recorded as `outputs["<action>.stderr"]` — e.g. `identify.stderr`, `explain.stderr` — **as an array of lines** (the stderr text split on `\n`, trailing empty element dropped), since multiline strings are awful in JSON. Absent when stderr was empty. `check-reciprocal` can adopt the same convention later (not in scope now).
- Adoption sequencing: validator accepts old and new shapes concurrently (legacy `raw`, optional `explain`/`.stderr` keys); the corpus converges to the new keyset whenever the next natural regeneration wave runs — no forced mass rewrite.
- DESIGN.md fixture-channels section + `fixtures/fixture.d.ts` updated accordingly; `fixtures/index.d.ts` (store schema) untouched.

# `agent-detect web` — open the registry website from the CLI

Written 2026-09-29, on the linux host, on the `website` branch. The website
(`site/`, plan 1790666509289) is deployed; this plan wires the released CLI to it: a `web` action
that builds the site's deep-link URLs and hands them to the platform's URL opener.

## goal

`agent-detect web [flags]` opens `https://agent-detect.bevry.workers.dev` (or just prints the URL
with `--no-open`), deep-linking exactly the way the site's own URL params work:

- **any dim** (`--harness=` / `--provider=` / `--model=`, individually or together): the index,
  filtered, scrolled to the results — `/?harness=<id>[&provider=<id>][&model=<id>]#registry`
  (the `#registry` anchor appears iff at least one dim was given);
- **all three dims**: the combo's result page instead — `/?agent=<agent_id>` (agent_id composed
  exactly like `setAgentId`: the three strict slugs dash-joined), plus `&platform=<platform>` when
  `--platform=` is given (it pins the result page's platform tab);
- **no dims**: the bare homepage.

## decisions

1. **CLI-side resolution, strict.** Every provided dim resolves through `canonicalFilterDim`
   against the rule tables — names, labels, and aliases accepted, exactly like the recipe-mode
   flags. An unresolvable dim exits 7 with the dims block (`missing specified agent (…)`), never a
   silent drop: the CLI knows the URL is dead before a browser is involved.
2. **`--platform` requires the complete combo.** The index ignores `?platform=` (it is an
   agent-page param), so `--platform` with a partial combo is exit 4 with a one-line reason.
   `--no-open` composes with everything.
3. **The URL prints to stdout in both modes.** Opening doesn't swallow the URL (wrapper scripts
   and copy-paste still get it); `--no-open` makes the print the whole effect — no opener spawn.
4. **The opener is the platform's own.** linux `xdg-open <url>`, macOS `open <url>`, Windows
   `cmd /c start "" <url>` — stdout/stderr ignored, child waited. An absent opener (`FileNotFound`)
   is exit 6 (incomplete environment preventing run) with the `--no-open` hint; README already
   documents it as the second optional dependency.
5. **`web` has a dedicated help topic.** `help web` / `web --help` print a `webUsage` block (the
   URL forms + flags), the way `trailer` has `trailerUsage`; `usage` gains the action line, the two
   new flags, and an example. The dev usage composes `usage`, so it inherits automatically.
6. **The URL builder is pure.** `buildWebUrl` in core.zig is allocation-only (no io), so
   `src/web.test.zig` can unit-test every shape: no dims → `/`; one/partial dims → the filter query
   + `#registry`; all three → `?agent=<h-p-m>`; `--platform` appended; canonical-slug composition.
7. **Released surface, not dev-gated.** The site is a user surface, so `web` is a released action;
   `isKnownAction` gains `"web"` (making `help web` resolve) and the dispatch lives in
   `mainInner`'s action parser. `--platform=`/`--no-open` parsed at top level are validated to the
   `web` action: given alongside any other action they are a conflicting argument (exit 3).

## surface

```
agent-detect web [--harness=H] [--provider=P] [--model=M] [--platform=PL] [--no-open]
```

Exit codes: 0 (opened / printed), 2 unrecognised argument, 3 conflicting argument
(`--platform=`/`--no-open` outside `web`), 4 missing required arguments (`--platform` on a partial
combo), 6 opener absent, 7 a provided dim resolved to no rule.

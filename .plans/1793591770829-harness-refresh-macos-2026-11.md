## goal

Bring every harness in the test matrix to its current release through the
harness's own supported install path, add the three missing harnesses that are
now real products (`dsh`, `codewhale`, and the MiniMax Code CLI), remove the
obsolete OpenCode v1/`opencode2` path, install the Cline, Kilo, and MiniMax Code
desktop clients through Homebrew casks where they exist, and then retest
detection and capture.

The matrix is extended only for maintained coding harnesses. Desktop apps get
install rows, not detection rules or fixtures, in this pass; a desktop client
joins the detection matrix only when its own rule, detector, and fixtures land
with it.

## non-goals

- No install of contributor-scope harnesses (`hermes`, `autoclaw`) or the
  pending `claude`/`codex`/`gemini`/`grok` list.
- No direct DMG/URL install when a Homebrew cask exists. Kilo Desktop has no
  cask as of 2026-11-02, so its DMG is not installed silently in this pass.
- No detection rules or fixtures for desktop clients yet. Cline Desktop, Kilo
  Desktop, and MiniMax Code Desktop are install-only rows here.
- No harness config, auth, key, or credential-store writes. Installs may write
  their own package files and PATH entries; that is the installer's job, not a
  config edit by this project.
- No global provider/model setting changes to make a capture pass. Use
  invocation-level flags or environment variables only; flag the rest.
- No retrospective edits to committed fixture contents. Re-run the channel.
- No release cut.

## decisions

1. **OpenCode has one id: `opencode`, and it means v2.** OpenCode v1 is legacy;
   v2 is stable. The `opencode2` registry row, `@opencode-ai/cli` package, and
   `/v2/install` custom branches are removed. The harness id stays `opencode`,
   and the npm fallback is repointed from v1 `opencode-ai` to v2 `@opencode/cli`.
   Homebrew core `opencode` (2.2.5) remains the macOS default; the
   `anomalyco/tap/opencode` formula is v1 and must not be installed.
2. **Reasonix 1.x is maintenance; 2.x is the active line.** Upgrade to 2.57.0.
   The documented Homebrew cask is currently unreadable under Homebrew
   7.0.11-148 (`undefined local variable staged_path`), so this host uses the
   npm package. That is an exception, not a preference change. If the cask
   becomes readable, move it back to Homebrew in a follow-up.
3. **DeepSeek products stay separate.** `dsh` is the DeepSeek Harness CLI;
   `codewhale` is the independent CodeWhale terminal agent (formerly the
   DeepSeek-TUI lineage). They get separate rules, detectors, invocations, and
   fixtures. Neither replaces the other.
4. **MiniMax products stay separate.** `mmx` is the MiniMax platform API CLI;
   `mcode` is the MiniMax Code coding harness. Keep `mmx` and add the harness
   under the canonical name `minimax-code` (label “MiniMax Code”, variation
   `mcode`). A harness and a provider may share a name because they are
   different tables.
5. **Homebrew is the first choice, then npm, then a harness-owned installer.**
   Brew formulae/casks get `brew update` + `brew upgrade`; npm packages get an
   unpinned global install/update; `uv` stays the Vibe source of truth.
6. **No version pins in the install registry or docs.** Pins go stale. The plan
   records the observed versions; the script always asks the package manager
   for the current stable release.
7. **npm lifecycle scripts are denied by default on this host.** `npm config
   get allow-scripts` is `false`. Most packages in the matrix need no scripts.
   `minimax-code` is the exception: its postinstall verifies the native SQLite
   install, and its optional `better-sqlite3` dependency runs
   `prebuild-install || node-gyp rebuild`. Without those scripts the CLI can
   install but cannot use its session database.
8. **`--allow-scripts` is an allow-list, not a blanket approval.** The mcode
   command names only `@minimax-ai/code` and `better-sqlite3`; it does not set
   `ignore-scripts=false` for the whole dependency tree. The residual risk is
   real: those two packages, or a compromised release of them, execute code as
   the user during install. The official MiniMax installer runs the same
   allow-list internally, and the release-archive path still needs
   `--allow-scripts=better-sqlite3`, so switching installers does not remove the
   risk. Disabling optional dependencies avoids the script but skips
   `better-sqlite3`, which leaves the CLI without its session database. Source
   trust plus the public npm registry is the practical mitigation; a
   container/VM is the only stronger isolation, and is out of scope.
9. **Deno and Bun are not selected for this matrix.** Deno can install npm
   packages globally (`deno install -g`) and supports `--allow-scripts`, and Bun
   can run Node packages and native addons, but neither is the harness's
   supported install path. Deno 2.9.8 happens to be installed here, but Bun is
   absent, and neither gives a simpler update command than the npm prefix
   already in use. `deno x`/`bunx`/`npx` are run-without-install tools; the
   daemon probes a persistent `dsh`/`mcode` binary on `PATH`, so they do not
   fit. Deno's global install also has to be re-run to update, while
   `npm update -g` and `brew upgrade` are the host's existing update paths.
10. **`codewhale` comes from its Homebrew tap.** The tap formula installs the
    checksum-verified release binaries for both `codewhale` and `codew`, and
    `brew upgrade codewhale` is the documented update path. The tap is
    third-party; trust it explicitly (Homebrew 7 requires tap trust) and do not
    bypass the check with a raw installer. The official curl installer is the
    fallback only if the tap cannot be trusted on this host.
11. **Captures are bounded.** Installing and from-identity work is local and
    zero-token. From-capture is token-consuming, so the first retest is one
    canonical combo per harness that has credentials; the rest is queued only
    after that passes. `dsh`, `mcode`, and possibly Reasonix will be blocked on
    credentials/trust and are recorded as such rather than forced.
12. **The daemon runs outside this agent session, but the agent can start it
    detached.** It refuses an in-session start by design; on macOS the per-user
    LaunchAgent gives it a clean launchd ancestry and a marker-free environment,
    and on Linux `setsid` + unsetting the rule markers does the same. Queueing,
    status, and log review stay here. Only platforms without a detached spawn
    (Windows in this repo) hand the start to the user in a terminal.
13. **Desktop clients are separate install rows and cask-first.** Cline Desktop
    is `cline-app` (the `cline` token is the CLI, not the app). MiniMax Code
    Desktop is `minimax-ai/tap/minimax-code --language=en`; the language flag is
    required for the overseas build and persists across upgrades. Kilo Desktop
    has no cask, so it is the one deliberate gap: do not install its DMG
    silently, and do not treat the `kilo` CLI formula as the desktop app. These
    apps are not added to the detection matrix until they get their own
    detectors and fixtures.

## install and update commands

Run after the plan is approved, in this order. Homebrew is updated once, then
only the named packages are upgraded; this avoids a blanket upgrade of unrelated
host packages.

```sh
# Homebrew CLI sources (current formulae/casks)
brew update
brew upgrade qwen-code
brew upgrade copilot-cli --cask
brew install Hmbown/deepseek-tui/codewhale

# Desktop clients (cask-first; Kilo has no cask yet)
brew install --cask cline-app
brew install --cask minimax-ai/tap/minimax-code --language=en

# npm sources (no version or tag pins: npm resolves the latest stable dist-tag)
npm i -g cline
npm i -g reasonix
npm i -g mmx-cli
npm i -g @deepseek-ai/dsh
npm i -g @minimax-ai/code \
  --include=optional --ignore-scripts=false \
  --allow-scripts=@minimax-ai/code,better-sqlite3

# uv source of truth
uv tool upgrade mistral-vibe
```

`opencode`, `kimi-code`, `pi`, `kilo`, `omp`, `crush`, `cursor`, and `goose` are
already current and are verified, not reinstalled. `cursor-agent --version`
currently fails because the macOS login keychain is locked; the cask is current,
so this is a verification follow-up, not an upgrade.

Desktop updates run through `brew upgrade --cask cline-app` and
`brew upgrade --cask minimax-ai/tap/minimax-code`; the MiniMax language choice
is persisted in the Caskroom metadata, so the English build survives upgrades.
Kilo Desktop is not installed: there is no cask, and the DMG is not used
silently.

If `brew install Hmbown/deepseek-tui/codewhale` refuses on trust, stop and ask;
do not replace it with a piped installer silently. The tap formula's checksums
are the verification.

## code changes

### 1. install registry — `scripts/install-harnesses.ps1`

- Remove the `opencode2` row, `$NpmPackage.opencode2`, and all `opencode2`
  custom-installer branches.
- Repoint `$NpmPackage.opencode` to `@opencode/cli` and `$BrewPackage.opencode`
  from the v1 `anomalyco/tap/opencode` formula to core `opencode` (v2); keep
  core Homebrew as the macOS first method, with Linux keeping npm first per the
  repo policy. Never use the v1 tap.
- Keep the existing `dsh` row (`@deepseek-ai/dsh`, all platforms) and correct
  its label if the developer-preview marker is stale.
- Add rows:
  - `codewhale` — probe `codewhale`, Homebrew tap
    `Hmbown/deepseek-tui/codewhale` on macOS/Linux; npm wrapper on Windows as
    the fallback (it downloads the same release binary).
  - `minimax-code` — probe `mcode`, npm `@minimax-ai/code`, all platforms.
- Keep the registry CLI-only: the desktop clients are cask installs run from
  the documented commands above, not probed by `-Check`. Adding a desktop app
  to the harness registry would give it a fake probe binary and a fake
  version check.
- Add a per-package npm-extra-args map so `minimax-code`'s install **and**
  upgrade both carry `--include=optional --ignore-scripts=false
  --allow-scripts=@minimax-ai/code,better-sqlite3`. Do not apply the flag to
  every npm package.
- Add explicit cask handling for `copilot` and `cursor` (`brew install --cask`,
  `brew upgrade --cask`), and keep `reasonix` on npm until its cask is readable.
- Keep `-Check` as the post-install source of truth: it prints the resolved
  binary and version for every row, including binaries in `~/.local/bin` or the
  npm global prefix.
- Do not add version pins anywhere.

### 2. rules — `src/lib/rules.zig`

Add three harness rules:

- `dsh` — label “DeepSeek Harness”; MIT; env markers `DSH_HOME`, `DSH_PROFILE`,
  `DSH_API_KEY` (value never emitted); binaries `dsh`, `dsh.exe`, `dsh.cmd`,
  `dsh.ps1`; variation “DeepSeek Harness CLI”.
- `codewhale` — label “CodeWhale”; MIT; env markers `CODEWHALE_HOME`,
  `CODEWHALE_CONFIG_PATH`, `CODEWHALE_MODEL`, `CODEWHALE_PROVIDER`,
  `CODEWHALE_TELEMETRY`; binaries `codewhale`, `codew`, plus Windows suffixes;
  variations `codew`, `CodeWhale CLI`.
- `minimax-code` — label “MiniMax Code”; MIT; env markers
  `MINIMAX_DATA_DIR`, `MAVIS_DATA_DIR`, `MCODE_DISABLE_TELEMETRY`,
  `DO_NOT_TRACK`; binaries `mcode`, `mcode.exe`, `mcode.cmd`, `mcode.ps1`;
  variation `mcode`.

Training postures are recorded only from verified sources; where the harness
docs are silent, use `NOASSERTION` (never guess `never`). The existing
`deepseek`/`deepseek-flash` and `minimax`/`minimax-code` provider rules cover the
observed provider dims; add model rules only for observed ids that are not
already ruled and that clear the evergreen policy.

### 3. detectors — `src/lib/core.zig`

Add one detector per harness and dispatch it by rule name:

- **CodeWhale** — env override first (`CODEWHALE_PROVIDER` +
  `CODEWHALE_MODEL`); then the active session's metadata in
  `~/.codewhale/sessions/<id>.json` (`metadata.model`,
  `metadata.model_provider`, newest session for the cwd); then
  `~/.codewhale/config.toml` (`provider`, `default_text_model`) as the
  committed default. Session metadata is the observed source; config is the
  fallback. Add the session file as an observation, not a fabricated config
  entry.
- **DeepSeek Harness** — env override if the CLI exposes one; otherwise read the
  newest materialized session under `$DSH_HOME/storages` (default `~/.dsh`).
  Sessions are per-project/per-id directories containing
  `session.vN.jsonl.zstd` (or raw `session.vN.jsonl` when compression is
  disabled); read the highest generation, decompress with the Zig std Zstandard
  decoder, and take `provider`/`model` from `request/header` or
  `assistant/message`. The profile-aware home comes from `DSH_HOME`; never
  write `settings.yaml`, `.credentials.yaml`, or a profile patch.
- **MiniMax Code** — profile-aware data dir: `MINIMAX_DATA_DIR`, then
  `MAVIS_DATA_DIR`, then `~/.minimax` (or `~/.minimax-<profile>`). Read
  `config.yaml` (`defaultModel` and provider config) as the committed default;
  read the active session from `v2/sqlite/runtime-state.sqlite`
  (`local_runtime_sessions.record_json`) and support the legacy
  `v2/chats/local-runtime.sqlite` shape during the migration window. Do not
  read or print credentials.

Every detector must degrade to partial detection honestly: an unresolved dim
stays unset, and the evidence claim names the file/field or env marker that
actually supplied the value.

## retest protocol

1. **Local build gate** — `zig build`, `zig build dev`, `zig build test`.
2. **Install gate** — `pwsh -File ./scripts/install-harnesses.ps1 -Check` and
   the individual version probes. Every matrix row must be installed and at the
   current version, except the documented contributor-scope rows. Desktop:
   `brew list --cask cline-app` and
   `brew list --cask minimax-ai/tap/minimax-code` must resolve; Kilo Desktop is
   documented as having no cask.
3. **Self-identification** — `./zig-out/bin/agent-detect identify` in this
   session must report `opencode`/`deepseek`/`deepseek-v4.1-flash` with agent id
   `opencode-deepseek-deepseekv41flash` and trailer
   `Assisted-by: OpenCode · DeepSeek V4.1 Flash <opencode-deepseek-deepseekv41flash@local>`.
   This also proves the provider switch from the OpenCode provider was detected
   live, not cached.
4. **From-identity sweep** — queue the new harnesses (and any changed matrix
   harness) with `--from-identity`; run the daemon outside this agent session;
   confirm the new identity fixtures and index-data entries.
5. **From-capture smoke** — one canonical combo per harness with credentials,
   in this order: existing harnesses first, then CodeWhale (its config has a
   DeepSeek key), then Reasonix if its folder trust is already granted. `dsh`
   and `mcode` stay queued/blocked until a credential or login exists.
6. **Failure review** — `fixtures status`, `daemon.log`, and
   `backlog.known_but_failed`; do not turn a credential/quota failure into a
   code change.
7. **Final local gate** — `zig build test`, `fixtures index --check`, and a
   final `install-harnesses.ps1 -Check` snapshot for the commit message.

Start the daemon detached on macOS:

```sh
scripts/launch-daemon-macos.sh start
scripts/launch-daemon-macos.sh status
```

The wrapper writes `~/Library/LaunchAgents/com.agent-detect.fixtures.plist` and
bootstraps it through launchd, so the daemon gets a clean ancestry and a
marker-free environment. Queueing, status, and log review continue here. A
clean `printf 'stop\n' > fixtures/daemon.ctl` stays stopped because the plist
uses `KeepAlive SuccessfulExit=false`; use `scripts/launch-daemon-macos.sh stop`
to unload and disable it.

## risks and blockers

- **Kilo Desktop has no cask** — Homebrew cask has no Kilo app and
  `Kilo-Org/homebrew-tap` ships only the `kilo` CLI formula. Installing the
  official DMG would be a direct URL install, so it is deferred rather than
  done silently.
- **MiniMax cask language** — `minimax-ai/tap/minimax-code` defaults to the
  mainland build. `--language=en` is required for the overseas/English build,
  and the choice persists in Caskroom metadata across `brew upgrade`.
- **Cline naming** — `brew install --cask cline` fails; the desktop cask token
  is `cline-app`. The npm `cline` package remains the CLI.
- **OpenCode provider credits** — the session moved to DeepSeek after the
  OpenCode provider ran out of free credits. Any from-capture run that depends
  on that provider may hit the same limit; record it as a quota blocker, not a
  detection bug.
- **`dsh` credentials** — `DEEPSEEK_API_KEY`/`DSH_API_KEY` are unset and the
  headless profile deliberately ignores the stored credential store. Detection
  can land and from-identity can pass; from-capture is blocked until the user
  supplies a launch environment or `$DSH_HOME/.env`. Do not write credentials.
- **`mcode` login** — `~/.minimax` is empty. Install and detection can land;
  from-capture waits for a user login or BYOK configuration.
- **Reasonix 2.x folder trust** — 2.x may refuse headless writes until
  `reasonix trust --dir ...` has been run. That is user state; do not write it.
- **CodeWhale tap trust** — Homebrew 7 requires explicit tap trust. If the host
  will not trust the tap, the official checksum-verified installer is the only
  fallback, and the plan records which path was used.
- **OpenCode v1/v2 collision** — both use `opencode`. Never install the v1 tap
  or the v1 npm package; verify `opencode --version` reports 2.x after any brew
  operation.
- **Cursor keychain** — `cursor-agent --version` is blocked by the locked
  login keychain. The cask is current; re-check after the user unlocks it.
- **Daemon guard** — the fixtures daemon refuses to start in an agent session;
  the retest cannot be completed from inside this conversation.
- **Token cost** — from-capture launches real model sessions. The bounded
  one-per-harness smoke keeps this intentional; a full matrix sweep needs a
  separate approval.

## acceptance criteria

- The install registry has no `opencode2`, no OpenCode v1 source, no stale
  version pins, and includes `dsh`, `codewhale`, and `minimax-code`.
- Every installed matrix harness reports its current version; the three new
  harnesses resolve through their own binaries.
- Cline Desktop and MiniMax Code Desktop are installed through their Homebrew
  casks; Kilo Desktop's missing cask is recorded instead of bypassed with a DMG.
- The new rules, detectors, invocations, and index entries are covered by tests;
  `zig build`, `zig build dev`, and `zig build test` pass.
- `fixtures index --check` passes and no fixture body was hand-edited.
- The current session identifies as
  `opencode-deepseek-deepseekv41flash` with the expected trailer, proving the
  provider switch is detected live.
- From-identity fixtures exist for the new harnesses; from-capture results (or
  explicit credential/trust blockers) are recorded for every matrix harness.
- Docs describe the new config locations, install policy, and OpenCode v2
  decision.

# plans.md

Project-wide plan conventions for **every** harness working on this
repo — referenced from [AGENTS.md](./AGENTS.md) (see
[meta.md](./meta.md) for the reference pattern). bevry-vibes/skills
has no `plans.md` skill yet, so these conventions are project-local
and to be upstreamed; they were previously recorded as `kilo.md`
tweaks, which this file retires by generalising them across harnesses.

## where plans live

Every plan file an agent generates goes to repo-root `.plans/` —
never a harness-private directory — named
`.plans/<epoch-ms>-<slug>.md`, so plans from different harnesses
share one chronological space. Historical plans migrated from
`.kilo/plans/` keep their names.

## provenance companion

Every plan records its provenance in an accompanying
`<plan>.prompts.md` companion: the original prompt that initiated
the plan and every followup prompt that shaped it — verbatim,
untruncated, in order — with timestamps only where the agent can
actually observe them (never fabricated), and the agent model that
generated it (as reported by the harness). The plan file itself only
links to the companion and never inlines prompts (inlined prompts
with plans confuse readers and agents).

## no condensed proposals

Never do condensed proposals for complicated changes. For non-trivial
design changes, write a proper proposal/comparison document (schema
options, concrete examples, trade-off tables, code-impact inventory)
before asking for a decision. Multi-choice tool questions alone are
not acceptable for complicated changes.

## commit the plan before `plan_exit`

The plan file and its `.prompts.md` companion are committed (per
[commits.md](./commits.md): build first, generated trailer) before
each `plan_exit`, so plan and prompt updates are traceable in git
history.

## plan introductions carry the `Assisted-by` line

A plan's introduction starts with the session's `Assisted-by` trailer
(generated by `./zig-out/bin/agent-detect trailer assisted-by`, never
cached or guessed) alongside the provenance companion link.

## crush session summaries at handoff

When a crush session hands off (context exhaustion or user request),
save every compaction summary the session produced into `.plans/` so
a future session can reconstruct the full history.

**Where crush keeps it.** Per-project sqlite at `.crush/crush.db`
(the per-project data dir is listed in
`%LOCALAPPDATA%\crush\projects.json`). Tables: `sessions` (id,
title, message_count, `created_at`/`updated_at`) and `messages`
(session_id, role, `parts`, `created_at`, `is_summary_message`).
Gotcha: the schema comment claims milliseconds, but the stored
values are **epoch seconds**. The main session is the row with the
largest `message_count` (the many 2-message "Untitled Session" rows
are title-generation side effects).

**What to extract.**

- Summaries: `messages` rows with `is_summary_message = 1`, ordered
  by `created_at`. The body is the concatenation of the `text` parts
  of the `parts` JSON array (skip `reasoning`/`finish` parts).
- User-prompt log: `role = 'user'` messages with at least one
  `text` part. Tool results come back as user-role messages with
  `function_call_response` parts and no text, so this isolates the
  real prompts.

**How (the pipeline that worked).**

1. `sqlite3 -json .crush/crush.db "SELECT ..."` dumps raw rows (the
   whole `parts` blob; no JSON paths in the shell), then a
   `tmp-*.ps1` run via `pwsh -NoProfile -File` parses `parts` with
   `ConvertFrom-Json`.
2. One plan file per summary:
   `.plans/<created_at × 1000>-session-summary-<n>-of-<count>.md`,
   standard header (`Assisted-by` generated by
   `./zig-out/bin/agent-detect trailer assisted-by`, companion
   link), body verbatim.
3. Companion `<plan>.prompts.md`: session metadata (id, harness
   combo, first/last prompt times) plus the prompt log, each prompt
   headed by its observed timestamp (`## <UTC+8 ts> (epoch <s>)`).
4. Write files with `[System.IO.File]::WriteAllText`, joining lines
   on "`n" (LF; never `Set-Content` for this).

**Pitfalls hit while doing it.**

- The mvdan/sh tool expands `$[0]` inside single quotes, so
  `json_extract(parts, '$[0].type')` inlined in a bash command
  silently becomes `0.type`; keep JSON paths out of the shell.
- PowerShell: `[long]$obj.Prop` binds the cast to `$obj`, not the
  property; parenthesize as `[long]($obj.Prop)`, or pass the JSON
  number (already Int64 after `ConvertFrom-Json`) straight into a
  typed parameter.
- PowerShell: `@($a, $arr, $b) -join "`n"` stringifies nested
  arrays as `System.Object[]`; flatten first (e.g.,
  `[void]$list.Add(...)` in a loop).
- Backticks inside PowerShell double-quoted strings are escape
  characters (a line-ending backtick is a continuation and breaks
  the parse); keep backtick-containing literals in single-quoted
  strings.
- The mvdan/sh tool has no `head`/`tail`/`ls -t`; use pwsh for text
  work.

`.crush/` is gitignored; never commit the database itself.
